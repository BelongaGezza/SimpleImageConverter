# v0.2.0 STEP Reading Research
## Simple Image Converter

**Date:** January 27, 2025  
**Status:** 🔬 **RESEARCH IN PROGRESS**  
**Goal:** Find viable solution for STEP file reading in Rust

---

## Problem Statement

**Current Situation:**
- `truck-stepio 0.3.0` does **not support STEP file input/reading**
- Library is designed primarily for STEP output (writing)
- STEP reading is blocked pending library support

**Objective:**
- Find viable alternative for STEP file reading
- Must integrate with existing mesh conversion pipeline
- Should be production-ready or near-production-ready
- Must be compatible with our license (MIT/Apache-2.0)

---

## Candidate Libraries

### Option 1: ruststep (STEP Parser Library) ⭐ **PROMISING**

**Library:** `ruststep = "0.4.0"`  
**License:** ✅ **Apache-2.0** (Fully compatible!)  
**Author:** ricosjp (same as truck library!)  
**Repository:** https://github.com/ricosjp/ruststep  
**Documentation:** https://ricosjp.github.io/ruststep/ruststep/index.html

**Status:** Parser library, needs conversion to mesh geometry

**Pros:**
- ✅ Pure Rust implementation
- ✅ Apache-2.0 license (fully compatible)
- ✅ Same author as truck (should integrate well!)
- ✅ Can parse STEP files (AP201, AP203 supported)
- ✅ Active project (0.4.0 released)
- ✅ Low-level access to STEP entities

**Cons:**
- ⚠️ Only provides parsing, not geometry conversion
- ⚠️ Would require manual conversion from STEP entities to mesh
- ⚠️ Complex conversion logic needed
- ⚠️ May not handle all STEP entity types

**Evaluation Status:**
- [x] License compatibility: ✅ Apache-2.0 (compatible)
- [ ] Test with sample STEP files
- [ ] Evaluate conversion complexity
- [ ] Check if can integrate with truck-modeling
- [x] Maintenance status: ✅ Active (0.4.0)

**Next Steps:**
- Create proof-of-concept using ruststep
- Test parsing sample STEP files
- Evaluate if can convert to truck Shell/Solid types

### Option 3: OpenCASCADE Technology (OCCT) FFI

**Library:** `opencascade-sys = "0.2.0"`  
**License:** ⚠️ **LGPL-2.1** (compatible but requires consideration)  
**Repository:** https://github.com/bschwind/opencascade-rs  
**Status:** Mature bindings to industry-standard CAD kernel

**Pros:**
- ✅ Industry-standard CAD kernel
- ✅ Comprehensive STEP support
- ✅ Robust geometry handling
- ✅ Well-documented
- ✅ Bindings available

**Cons:**
- ⚠️ Requires FFI (Foreign Function Interface)
- ⚠️ C++ library underneath (larger binary, ~50-100MB+)
- ⚠️ More complex integration
- ⚠️ Platform-specific builds may be needed
- ⚠️ Binary size increase (significant)
- ⚠️ LGPL license requires consideration

**Evaluation Status:**
- [x] Rust binding availability: ✅ Available (0.2.0)
- [ ] Evaluate integration complexity
- [ ] Test build process (may be complex)
- [ ] Check binary size impact (likely significant)
- [x] License compatibility: ⚠️ LGPL-2.1 (needs review)

**Note:** LGPL-2.1 is generally compatible with MIT/Apache-2.0 for library usage, but may require distribution considerations. Binary size is likely to be a major concern.
